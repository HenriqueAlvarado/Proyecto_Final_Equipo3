4.1 Button.jsx
--------------------------------------------------------------------------------
Descripcion:
  Boton reutilizable con soporte para multiples variantes visuales, tamanos
  y estado de carga. Cubre todos los casos de uso de la aplicacion.

Props:
  Prop        Tipo        Default     Descripcion
  ----------  ----------  ----------  ----------------------------------------
  children    ReactNode   -           Contenido del boton (texto o icono)
  variant     string      'primary'   Estilo visual del boton
  size        string      'md'        Tamano del boton
  disabled    boolean     false       Deshabilita interaccion
  loading     boolean     false       Muestra spinner y deshabilita el boton
  onClick     function    -           Manejador del evento clic
  type        string      'button'    Tipo HTML (button, submit, reset)
  fullWidth   boolean     false       Ocupa el 100% del ancho disponible

Variantes (variant):
  'primary'   Fondo azul (#1a73e8), texto blanco. Accion principal.
  'secondary' Fondo verde (#34a853), texto blanco. Accion secundaria.
  'danger'    Fondo rojo (#ea4335), texto blanco. Acciones destructivas.
  'outline'   Fondo transparente, borde y texto azul. Accion alternativa.

Tamanos (size):
  'sm'  Padding reducido, fuente 14px. Para tablas y espacios compactos.
  'md'  Padding estandar, fuente 16px. Uso general.
  'lg'  Padding amplio, fuente 18px. Llamadas a accion destacadas.

Accesibilidad:
  - aria-disabled="true" cuando loading o disabled es true
  - El spinner incluye aria-hidden="true" para no ser leido por lectores
  - Mantiene el foco visible con outline en modo teclado

Ejemplos de uso:
  <Button variant="primary" type="submit" loading={isLoading}>
    Guardar
  </Button>

  <Button variant="danger" size="sm" onClick={handleDelete}>
    Eliminar
  </Button>

  <Button variant="outline" fullWidth onClick={handleCancel}>
    Cancelar
  </Button>

5. COMPONENTES DE AUTENTICACION (src/components/auth/)
================================================================================

--------------------------------------------------------------------------------
5.1 LoginForm.jsx
--------------------------------------------------------------------------------
Descripcion:
  Formulario de inicio de sesion para personal clinico (recepcionistas,
  medicos y directores). Se muestra en el tab "Personal clinico" de LoginPage.

Campos:
  - Correo electronico (type="email", requerido)
  - Contrasena (type="password", requerido)

Flujo de autenticacion:
  1. Usuario ingresa credenciales
  2. Validacion local (formato email, campos no vacios)
  3. Llamada a authService.login(email, password)
  4. Si exitoso: guarda token y user en AuthContext y localStorage
  5. Navega a /dashboard via useNavigate()
  6. Si error: muestra mensaje del servidor

Validaciones:
  - Email: formato valido (regex)
  - Password: campo no vacio

--------------------------------------------------------------------------------
5.2 LoginPacienteForm.jsx
--------------------------------------------------------------------------------
Descripcion:
  Formulario de inicio de sesion para pacientes. Se muestra en el tab
  "Soy paciente" de LoginPage.

Campos:
  - Correo electronico (type="email", requerido)
  - Contrasena (type="password", requerido)

Flujo de autenticacion:
  1. Paciente ingresa credenciales asignadas por la recepcionista
  2. Llamada a authService.loginPaciente(email, password)
  3. El backend busca en tabla "pacientes" (no en "usuarios")
  4. Si exitoso: guarda token con rol 'paciente' en AuthContext
  5. Navega a /mis-citas via useNavigate()

Nota: Las credenciales del paciente son asignadas por la recepcionista
al momento de registrar al paciente en el sistema.

11.2 Descripcion de Paginas
-----------------------------

LoginPage.jsx
  Pagina de inicio de sesion con dos tabs:
  - "Personal clinico": muestra LoginForm.jsx
  - "Soy paciente": muestra LoginPacienteForm.jsx
  Redirige a /dashboard (staff) o /mis-citas (paciente) si ya hay sesion.

DashboardPage.jsx
  Envuelve el componente Dashboard.jsx.
  Muestra estadisticas del dia actual.

AgendaPage.jsx
  Pagina principal de gestion de citas.
  Orquesta AgendaView, CreateAppointmentForm, EditAppointmentForm
  y CancelAppointmentModal.
  Maneja el estado de que modal/formulario esta abierto.

11.3 Proteccion de Rutas
--------------------------

ProtectedLayout:
  Componente que envuelve todas las rutas autenticadas.
  Si no hay usuario en AuthContext, redirige a /login.
  Renderiza Navbar + Sidebar + contenido de la ruta.

HomeRedirect (/):
  Redirige segun el rol del usuario autenticado:
  - paciente  -> /mis-citas
  - staff     -> /dashboard
  - sin sesion -> /login

LoginPage (redireccion inversa):
  Si el usuario ya tiene sesion activa y navega a /login,
  redirige automaticamente a su pagina de inicio.

12.1 api.js - Configuracion Base de Axios
------------------------------------------
Instancia Axios compartida por todos los servicios.

Configuracion:
  baseURL:  REACT_APP_API_URL (definido en .env)
  timeout:  10,000 ms (10 segundos)

Interceptor de Request:
  - Lee el token JWT de localStorage
  - Agrega header: Authorization: Bearer <token>
  - Se ejecuta en cada peticion automaticamente

Interceptor de Response:
  - Si el servidor responde con 401 (no autorizado):
    * Limpia token y user de localStorage
    * Redirige a /login
  - Extrae el mensaje de error del response para mostrarlo al usuario

13. CONTEXTO Y HOOKS (src/contexts/ y src/hooks/)
================================================================================

--------------------------------------------------------------------------------
13.1 AuthContext.jsx
--------------------------------------------------------------------------------
Descripcion:
  Contexto global de React que maneja el estado de autenticacion en toda
  la aplicacion. Persiste la sesion en localStorage.

Valores que provee:
  Valor           Tipo      Descripcion
  --------------  --------  --------------------------------------------------
  user            object    Usuario autenticado o null si no hay sesion
  login           function  Autentica personal clinico
  loginPaciente   function  Autentica pacientes
  logout          function  Cierra la sesion y limpia el estado
  loading         boolean   true mientras verifica sesion al cargar la app

Estructura del objeto user:
  {
    id:       number,
    nombre:   string,
    apellido: string,
    email:    string,
    rol:      'recepcionista' | 'medico' | 'director' | 'paciente'
  }

Persistencia:
  - Al hacer login: guarda token y user en localStorage
  - Al cargar la app: recupera sesion de localStorage si existe
  - Al hacer logout: elimina token y user de localStorage

--------------------------------------------------------------------------------
13.2 useAuth.js
--------------------------------------------------------------------------------
Hook personalizado para acceder al AuthContext desde cualquier componente.

Retorna: { user, login, loginPaciente, logout, loading }

Uso:
  import { useAuth } from '../hooks/useAuth';

  const { user, logout } = useAuth();

--------------------------------------------------------------------------------
13.3 useForm.js
--------------------------------------------------------------------------------
Hook personalizado para manejo generico de formularios con validacion.

Funcionalidad:
  - Maneja el estado de los campos del formulario
  - Ejecuta validaciones por campo
  - Retorna errores de validacion por campo
  - Provee funcion handleChange para actualizar campos

Uso tipico:
  const { form, errors, handleChange, validate } = useForm(
    { email: '', password: '' },
    validationRules
  );

  # Sincronizar build con el bucket S3

  # URL de produccion:
  # http://medisync-web-20260501.s3-website-us-east-1.amazonaws.com
