4. HISTORIAS DE USUARIO IMPLEMENTADAS EN EL MVP

HU-01: Login de recepcionista (web)

6. ENDPOINTS DE LA API (MVP)
--------------------------------------------------------------------------------

Autenticacion:
  POST   /api/auth/login              Login staff (recepcionista, medico, director), retorna JWT
  POST   /api/auth/login-paciente     Login paciente, retorna JWT con rol 'paciente'
  POST   /api/auth/logout             Logout (cliente elimina token)
  POST   /api/auth/register           Crear usuario staff (solo director)
  GET    /api/auth/usuarios           Listar usuarios staff (solo director)
  PATCH  /api/auth/usuarios/:id/toggle Activar/desactivar usuario (solo director)
  GET    /api/auth/mis-citas          Citas del paciente autenticado

Citas:
  GET    /api/citas?fecha=YYYY-MM-DD  Citas por fecha
  POST   /api/citas                   Crear cita
  PUT    /api/citas/:id               Modificar cita
  PATCH  /api/citas/:id/cancelar      Cancelar cita
  GET    /api/citas/mis-citas         Citas del medico autenticado

Pacientes:
  GET    /api/pacientes               Listar todos (incluye curp y direccion)
  GET    /api/pacientes/buscar?q=     Buscar por nombre/email/CURP
  GET    /api/pacientes/:id           Detalle completo de paciente
  POST   /api/pacientes               Registrar paciente (con password)
  DELETE /api/pacientes/:id           Borrado logico (solo recepcionista/director)

Medicos:
  GET    /api/medicos                 Listar todos
  GET    /api/medicos/:id             Detalle de medico

Health check:
  GET    /health                      Estado del servidor

9. ERRORES ENCONTRADOS Y SOLUCIONES (MVP)
--------------------------------------------------------------------------------

ERROR 1: npm install timeout
Descripcion: npm install de react-scripts tarda mas de 2 minutos y el comando
             sincrono expira.
Solucion: Ejecutar npm install como proceso en background con controlPwshProcess
          y esperar con Start-Sleep antes de verificar el resultado.

ERROR 2: Build con IP vieja quemada
Descripcion: Despues de cambiar la IP en .env, el build seguia usando la IP
             anterior porque el proceso de build estaba en cache.
Solucion: Eliminar la carpeta build/ antes de hacer npm run build:
          Remove-Item -Recurse -Force build
          npm run build

ERROR 3: IP 100.31.x.x no accesible desde internet
Descripcion: AWS Academy asigna IPs en el rango 100.x.x.x (Carrier-Grade NAT)
             que no son accesibles desde dispositivos externos a la red de AWS.
Solucion: Asignar una Elastic IP real (3.219.251.228) al EC2.

ERROR 4: ERR_SSL_PROTOCOL_ERROR en celular
Descripcion: Chrome en movil fuerza HTTPS automaticamente. El S3 static hosting
             solo sirve HTTP, causando ERR_SSL_PROTOCOL_ERROR en Chrome movil.
Solucion: Usar un navegador que respete HTTP sin forzar HTTPS, como Firefox
             o Samsung Internet. El sistema funciona correctamente en HTTP.
             No se requiere cambiar a HTTPS para el alcance del proyecto.
Nota: Esta es una limitacion de ciertos navegadores moviles, no del sistema.
      El frontend en S3 HTTP es la arquitectura definitiva para este proyecto.

ERROR 5: CORS timeout
Descripcion: El frontend recibia "timeout of 10000ms exceeded" al intentar
             conectarse al backend.
Causa: La configuracion de CORS usaba process.env.FRONTEND_URL que tenia
       el valor "*" como string, pero Express no acepta "*" como string en
       la opcion origin.
Solucion: Cambiar la configuracion de CORS en index.js para usar una funcion
          callback que acepta cualquier origen:
          origin: (origin, callback) => { callback(null, true); }

ERROR 6: PM2 pierde procesos al reiniciar el lab
Descripcion: Cuando el lab de AWS Academy se pausa y reinicia, PM2 no
             recupera automaticamente los procesos aunque se haya ejecutado
             pm2 save.
Causa: El lab reinicia la instancia EC2 completamente, perdiendo el estado
       de PM2 en memoria.
Solucion: Cada vez que se reinicia el lab, conectarse por SSH y ejecutar:
          pm2 start src/index.js --name medisync-api

ERROR 7: Credenciales AWS expiradas
Descripcion: Las credenciales de AWS Academy expiran cuando el lab se pausa.
             Comandos como aws s3 sync fallan con AccessDenied.
Solucion: Obtener nuevas credenciales desde Canvas > AWS Details > Show
          y ejecutar aws configure set para cada valor.

ERROR 8: IP del EC2 cambia al reiniciar
Descripcion: Cada vez que el lab se pausa y reinicia, AWS Academy asigna
             una nueva IP al EC2 (de 54.196.144.76 a 100.31.109.89).
Solucion: Asignar Elastic IP fija (3.219.251.228) que persiste entre reinicios.

ERROR 9: SSH con PEM file - permisos incorrectos
Descripcion: Windows requiere permisos especificos en el archivo .pem para
             que SSH lo acepte.
Solucion:
    icacls "archivo.pem" /inheritance:r
    icacls "archivo.pem" /grant:r "%USERNAME%:R"

ERROR 10: git push rechazado (non-fast-forward)
Descripcion: El repositorio remoto tenia commits que no existian localmente
             (MediSync_Wireframes.html subido por otro miembro del equipo).
Solucion: Hacer git pull primero para integrar los cambios remotos, luego push.
          Se uso --no-edit para evitar abrir el editor vim para el mensaje
          de merge.
